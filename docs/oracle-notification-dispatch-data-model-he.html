Oracle Notification Dispatch Lab - אפיון מודל נתונים

סוג מסמך: אפיון מודל נתונים לשכבת בסיס הנתונים.

פרויקט: Oracle Notification Dispatch Lab.

תחום עסקי: מערכת דמיונית להפצת הודעות ומסרים רב-ערוצית.

שפת האפיון: עברית. שמות אובייקטים, עמודות ותגיות טכניות נשארים באנגלית לצורך DDL ו-Codex.

סטטוס: טיוטת אפיון ראשונה לסקירה.

1. מטרת מודל הנתונים

מטרת מודל הנתונים היא להגדיר שכבת בסיס נתונים עבור מערכת דמיונית שמנהלת בקשות להפצת הודעות ומסרים בערוצים שונים. המערכת אינה שולחת הודעות בפועל ואינה מתחברת לספקים אמיתיים. היא מנהלת את המידע הנדרש כדי לתאר הודעות, ערוצים, נמענים, פריטי הפצה, ניסיונות שליחה, תגובות ספק דמיוניות ולוג ביקורת.

החלטת יסוד: גוף ההודעה תלוי בערוץ. לכן תבנית הודעה היא ישות לוגית, והתוכן בפועל נשמר לפי שילוב של תבנית וערוץ.
החלטת יסוד: נמענים מגיעים ממערכת חיצונית. המערכת שומרת נמען מקומי לפי מזהה חיצוני ייחודי, מקשרת אותו לפריטי הפצה, ושומרת snapshot של פרטי הנמען והתוכן בזמן יצירת פריט ההפצה.
החלטת יסוד: Git הוא מקור האמת. כל אובייקט DB חייב להיות ניתן ליצירה מתוך קובצי SQL מנוהלים ב-Git.

2. הנחות נפח לשנה ראשונה

המספרים הבאים הם אומדני תכנון לצורך קבלת החלטות על אינדקסים, חלוקת טבלאות, partitioning ו-retention. הם אינם נתוני אמת ואינם מייצגים מערכת ארגונית אמיתית.

מדד אומדן לשנה הערה
נמענים ייחודיים300,000נמענים ממערכות חיצוניות, נשמרים פעם אחת לפי מזהה חיצוני.
יעדי ערוץ לנמען600,000-1,000,000ייתכנו כמה ערוצים או כמה יעדים לאותו נמען.
תבניות הודעה לוגיות100-1,000תבנית עסקית אחת יכולה לקבל תוכן שונה לכל ערוץ.
בקשות הפצה1,200,000כ-100,000 בקשות בחודש.
פריטי הפצה60,000,000ממוצע 50 נמענים/ערוצים לבקשת הפצה.
ניסיונות שליחה72,000,000ממוצע 1.2 ניסיונות לפריט, כולל retries דמיוניים.
תגובות ספק דמיוניות72,000,000תגובה אחת בממוצע לכל ניסיון.
אירועי audit100,000,000+עשוי להיות גדול מאוד אם מתעדים כל שינוי סטטוס.

3. כלל Partitioning

כלל תכנון: כל טבלה שצפויה לעבור 2GB לאחר כשנה של שימוש חייבת לקבל באפיון דרישת partitioning.

ברירת המחדל לטבלאות גדולות היא: 

Range partitioning by time column
Default granularity: monthly partitions

מפתחות partition מומלצים לפי סוג טבלה:

סוג טבלה מפתח partition מומלץ
בקשות הפצהREQUESTED_AT
פריטי הפצהCREATED_AT
תוכן snapshot לפריט הפצהCREATED_AT
ניסיונות שליחהSTARTED_AT
תגובות ספקRECEIVED_AT
AuditCREATED_AT

הערה: לפני מימוש פיזי של partitioning יש לוודא התאמה לגרסת Oracle, למהדורה וליכולות סביבת המעבדה.

8. הערות ל-Codex לפני יצירת DDL

אין לתת ל-Codex "להמציא" מודל נתונים. Codex צריך לקבל את האפיון הזה כמקור דרישות ולייצר DDL בהתאם.

כאשר תינתן משימת DDL ל-Codex, עליו לייצר:

  • קובצי SQL ליצירת כל הטבלאות.
  • Comments לכל טבלה.
  • Comments לכל עמודה.
  • Constraints מלאים.
  • Indexes לפי האפיון.
  • Partitioning לטבלאות שמסומנות כ-partitioning_required: YES.
  • קובצי seed לטבלאות reference.
  • בדיקות object inventory.
  • בדיקות invalid objects.
  • מטריצת הצלבה בין דרישות, טבלאות, עמודות, constraints ובדיקות.
